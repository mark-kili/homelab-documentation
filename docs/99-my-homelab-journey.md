# My Homelab Journey

## Why I Started

This project began with an unused HP Victus gaming laptop.

Instead of allowing the laptop to sit unused, I decided to repurpose it into a home server.

My goal wasn't simply to host applications.

My goal was to learn.

I wanted practical experience with Linux, Docker, networking, databases, and modern infrastructure.

---

## The Beginning

Like many people starting their homelab journey, I knew very little.

I began with Debian because I wanted to understand Linux from the ground up.

Although Debian provided a great learning experience, I eventually migrated to Ubuntu Server after deciding it better matched the direction I wanted to take with the project.

Looking back, that migration taught me an important lesson:

Changing direction isn't failure—it's part of learning.

---

## Discovering Docker

One of the biggest turning points in this project was discovering Docker.

Before Docker, I installed applications directly on the operating system.

As more services were added, they became increasingly difficult to organize and maintain.

Docker completely changed the way I think about deploying software.

Today, nearly every application in my home lab runs inside containers.

---

## Beyond Self-Hosting

As my confidence grew, the home lab became much more than a place to host applications.

It became the infrastructure supporting my own software projects.

Applications such as QuickPark and MaliHub rely on technologies that I first learned while building this environment.

This made the home lab an extension of my software development process rather than a separate hobby.

---

## The Challenges

Not everything worked on the first attempt.

I encountered networking issues.

Docker configuration mistakes.

Broken containers.

Operating system migrations.

Reverse proxy problems.

Database configuration challenges.

Every obstacle became an opportunity to learn.

Looking back, troubleshooting taught me just as much as successful deployments.

---

## What This Project Means To Me

This repository is more than documentation.

It represents my progress.

It records the decisions I made, the mistakes I learned from, and the technologies I explored.

It also reminds me that meaningful learning comes from building real systems rather than simply reading about them.

---

## Looking Forward

This project is still evolving.

There are many technologies I have yet to explore, including Kubernetes, Infrastructure as Code, advanced monitoring, automation, AI workloads, and high-availability systems.

As those technologies become part of my home lab, this documentation will continue to grow alongside them.

---

## Final Thoughts

When I started this project, my objective was simply to learn Linux.

Today, I have a much broader understanding of infrastructure, networking, Docker, databases, self-hosting, and system administration.

There is still much more to learn, and that is what makes this project exciting.

This repository is a snapshot of that journey—a reminder of where I started, what I have built, and where I hope to go next.
